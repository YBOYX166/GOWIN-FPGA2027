> 最后更新：2026-10-11

## 0. 一句话说清楚

在一块 **Tang Nano 4K（GW1NSR-4C）** 上用 FPGA 逻辑产生 **4 路舵机 PWM**，
通过**串口**接收上位机指令来手动微调 4 个舵机；配一个 **Tkinter 上位机**
（滑块控制 + 录制/回放 + 时间轴编辑）。逻辑做成**可移植**的，
等 **138K（GW5AT-138）** 开发板到货后直接搬过去。

**为什么要先在 4K 上写**：138K 的板子当时还没到，但舵机控制逻辑和芯片无关，
先在便宜的 4K 上把功能调通，移植时只改 `CLK_FREQ` 和约束文件。

| 信号 | 引脚 | 说明 |
|---|---|---|
| `Clk` | **45** | 27 MHz 板载晶振 |
| `Led` | **10** | 心跳灯。**引脚 10 = MODE1**，要当 IO 用必须在 P&R 里加 `set_option -use_mode_as_gpio 1` |

| `servo[3]` | **40** | 4 号舵机 |

### ⚠️ 供电（务必遵守）

```
舵机必须用【独立 5V 电源，≥5A】，绝不能从 FPGA 板取电
舵机电源的 GND 必须和 FPGA 的 GND 接在一起（共地）
```

4 个舵机同时动作的峰值电流可以到 5A 以上，从板子上取电必然把 FPGA 拉复位。

## 4. 串口协议

**波特率 115200，8N1**

### PC → FPGA

```
XYYY        4 位 ASCII 数字
 │└┴─ 角度 000-180
 └─── 舵机编号 1-4
```

例子：

| 发送 | 含义 |
|---|---|
| `1090` | 1 号舵机 → 90° |
| `2180` | 2 号舵机 → 180° |
| `4000` | 4 号舵机 → 0° |

- 编号必须是 1-4，角度必须 ≤180，**否则回 `ERR` 且不动作**
- **收到非数字字符会重新同步**（防止被截断的帧误触发）
- **不需要换行符**，凑满 4 位数字即触发

> **`SCALE_360 = 0`**：收到的值**直接就是角度**。
> 早期误以为范围是 0-360，做过一层 ×2 映射，现已改为直通。
> 若改成 1，上位机要同步加 `--scale360 1`，否则角度差一倍。

### FPGA → PC（三种，每秒/每条都发）

```
① 开机横幅（上电 500ms 后，2 行 60 字符）
② 心跳（每秒一次）
   A ddd ddd ddd ddd          <- 4 路当前的**原始值**，右对齐3位
③ 指令回复（每条指令处理完后）
   S<编号>=<原始值3位> A<角度3位>
   ERR                        <- 编号非法或角度超范围
```

**出问题时靠这三样定位**：看不到横幅 = TX 或串口不对；
有横幅但发指令没回复 = RX 不对；回复是乱码 = 波特率不对。

## 5. 上位机（`tools/servo_gui.py`）

```bash
/usr/bin/python3 tools/servo_gui.py            # 默认 --scale360 0
```

> **注意用 `/usr/bin/python3`**：系统自带 3.9 同时有 tkinter 和 pyserial；
> miniforge 的 python3 缺 pyserial。

### 界面分 6 块

| 区块 | 功能 |
|---|---|
| 顶部 | 串口选择 / 连接 / 刷新 |
| **滑块** | 4 路 0-180°，拖动即发指令（**60ms 节流**，避免事件风暴刷爆串口）|
| 按钮 | 全部回中位 90° / 全部 0° / 全部 180° / 清空日志 |
| **录制/回放** | 录制、JSON 存档、变速（0.25-4x）循环回放、**起始位** |
| **动作编辑** | **时间轴编辑器** —— 让四路同时动 |
| 回读 / 日志 | 心跳显示 + 收发日志（按类型着色）|

### 录制 / 回放

- **录制点挂在发送节流里**，所以记下来的是**真正写进串口的东西**，带相对时间戳
- 存档是自包含 JSON：`scale360`、`start_pose`、`duration`、`events`
- 回放**绕开 `pending` 直发** —— 因为 `pending` 是"同一路只留最新值"的
  合并机制，回放走它会把连续的同路指令合并掉，时间轴就不原样了
- 回放开始时**对记录做快照**，所以回放当中编辑时间轴不会影响正在播的

### 时间轴编辑（**让四个舵机同时动**）

**为什么需要**：录制时一次只能拖一个滑块，时间戳天然错开，
回放永远是"你一下我一下"。

```text
  舵机1  ●                    ← 蓝点 = 一条动作
  舵机2     ●                 ← 红点 = 已选中
  舵机3        ●
  舵机4           ●
         0s    0.5s   1.0s
```

| 鼠标 | 作用 |
|---|---|
| 单击圆点 / **Shift+单击** | 选中 / **加选** |
| 空白处单击 | 取消选中 |
| 按住拖动 | 改时间（按「吸附」栅格量化）|
| 滚轮 / 双击圆点 | 缩放 / 改角度 |

| 按钮 | 作用 |
|---|---|
| **对齐选中** | **落到同一时刻 —— 这就是"同时动"** |
| 吸附全部 | 所有时间量化到栅格，把"差一点点"的自动并成一组 |
| 整条通道平移 | 某一路整体提前/推后 N 毫秒 |
| 合并重叠 | 同一路连续重复的相同角度只留第一条 |
| 删除 / 撤销 / 全选 | **每步可撤销**（保留 80 步；拖动整段算一步）|

**标准三步**：四路各自"到位"的那条 Shift 多选 → 「对齐选中」 → 「▶ 回放」

### 起始位（保证回放可复现）

- **开始录制时自动记下当时的四路位置**
- **回放时先发这 4 条指令回位**，**等设定时间**（默认 600ms，按舵机速度调）
  让舵机真的到位，**然后才走时间轴**
- 没有它，回放会从"当前姿势"开始 —— 夹子可能正夹着东西、手臂可能停在半路，
  **第一段动作完全走样，每次结果都不一样**

> ⚠️ **已知缺口**：`tools/servo_1011_*.json` 这两份早期记录是在加
> 起始位功能**之前**保存的，里面 `start_pose` 是 `null`。
> 直接回放会报警告。解决办法：载入后点「以当前位置为起始」补一个。

cd 4k

**脚本依赖 Gowin EDA 装在 `/Applications/GowinIDE.app`**，
并且要设 `DYLD_LIBRARY_PATH` 和 `DYLD_FRAMEWORK_PATH`（脚本里已处理）。

### 烧录

> ⚠️ **烧录前必须完全退出 Gowin IDE**（Cmd+Q）。
> IDE 占着 USB 电缆，`programmer_cli` 会报 `Cable open failed`。
> **这也是"烧录一直崩溃"的真正原因。**

```bash
PROG="/Applications/GowinIDE.app/Contents/Resources/Gowin_EDA/Programmer"
IDE="/Applications/GowinIDE.app/Contents/Resources/Gowin_EDA/IDE"

# ① 烧到 SRAM（立刻生效，掉电丢失）—— 这一步是可靠的
env DYLD_LIBRARY_PATH="$PROG/lib:$IDE/lib" DYLD_FRAMEWORK_PATH="$PROG/lib:$IDE/lib" \
  "$PROG/bin/programmer_cli" -d GW1NSR-4C --operation_index 2 \
  --fsFile 4k/fs/servo_serial.fs

# ② 想掉电保存（片内 Flash）—— 目前不可靠，见 §8
... --operation_index 6
```

**验证烧进去的是什么**：

```bash
... --operation_index 0        # Bypass，读 User Code
# User Code 应该等于 .fs 头里的 CheckSum，当前是 0x000017E3
```

**操作索引对照**（从 `programmer.json` 挖出来的）：

| index | 操作 |
|---|---|
| 0 | Bypass（只读 ID/UserCode/Status）|
| 1 | Reprogram（从 Flash 重加载）|
| 2 | **SRAM Program** ✅ 可靠 |
| 5 / 6 | embFlash Erase,Program / +Verify |
| 8 / 9 | exFlash Erase,Program / +Verify |
| 13 | exFlash ... in bscan（**不限配置模式**）|
| 24 | SRAM Erase |

## 8. ⚠️ 未解决的问题（接手请从这里开始）

### 8.1 🔴 夹子会周期性松开 —— **未定位**

**现象**（用户原话整理）：

> 夹子（3 号）夹住东西后，我一动其他舵机，它自己会有一个**反复松爪子**的动作。
> 空载时也会 —— 只要别的舵机动作，3 号就跟着动一下。

**已经排除的**：

**① 固件不可能产生这个效果 —— 有网表级证明**

```
滑块3 → 指令 "3090"（id=3）
  → servo_cmd 只写 angle[23:16]（CE = n3042_3，3 号字节专属）
  → servo_pwm_1 的输入只有 cmd_angle[23:16]（模块端口就隔离了）
  → 附加输入 n1493_5 也只依赖 cmd_angle[23..18]
  → servo_d_1[2] → servo_2_obuf → 引脚 41
```

- 4 个输出脚各自独立驱动，无共享
- 唯一的共享信号是复位 `n86_6 = por_n` —— **一次性**上电复位，
  20ms 后拉高**永不变化**
- 全工程只有 1 个 `MULT9X9`（在 `servo_cmd` 里），4 路 PWM **没有共享乘法器**
- GUI 侧也验过：只拖 4 号只发 `4180`，穷举无串扰

**⇒ 拖其他滑块时，引脚 41 上的 PWM 脉宽一个纳秒都没变。**

**② 用户说"总电压没问题"** —— 但**这个结论不成立**：
普通万用表测的是平均值，采样率 ~3Hz；舵机启动的电流尖峰只持续几十微秒，
**直流档根本采不到**。

**剩下的可能（按可能性排序）**：

| # | 假设 | 怎么验证 |
|---|---|---|
| 1 | **电源瞬态跌落** | 万用表切 **MIN/MAX 档**再测；或示波器看波形 |
| 2 | **地线反弹** | 4 个舵机的 GND 是串在一起的吗？改**星形接地** |
| 3 | **舵机内部堵转保护在循环** | **夹好后手离开鼠标，盯 30 秒** —— 如果它自己周期性松，就是舵机自己的问题，和其他舵机无关 |
| 4 | **信号线噪声耦合** | 信号线和自己的地**拧成双绞**；远离其他舵机的**电源线**（那上面是 2~3kHz、几安培、边沿很陡的斩波电流）|
| 5 | 机械/振动耦合 | **用手推机械臂**（不要用电驱动），如果一推就松 → 机械问题 |

**为什么堵转的舵机特别脆弱**：

```
正常转动：电流 200~500mA，有反电动势，控制环稳定
堵转：    电流 2~3A，反电动势为零，误差恒定在最大值
          -> 电机满占空比输出，没有任何抗扰余量
```

**「夹到东西 + 拉到 180 度」是可能的最坏情况**（180° 是机械行程尽头）。

**还没试过的固件侧实验**：做一个**关掉串口发送**（心跳+回复全停）的版本。
如果关掉后症状消失，说明是引脚 44 的串口活动耦合过去的 ——
这是唯一还和固件沾边的可能。

### 8.2 🟡 掉电不保存

**用户需求**：固件一直待在板子里，掉电重上电还能跑。

**实测结果**：

| 操作 | 结果 |
|---|---|
| `exFlash`（按配置模式）| ❌ `spi flash not found` |
| `exFlash ... in bscan`（不限配置模式）| ❌ `Spi flash not found` |
| `embFlash Erase,Program,Verify` | ⚠️ 跑到校验，**`Verify Failed at 106`** |
| `embFlash Erase,Program`（去掉校验）| ❌ `POR Down` |
| `embFlash 2nd` | ❌ `POR Down` |
| 关掉 bitstream 的 `SecurityBit` 后重试 | ❌ 仍 `POR Down` |
| **SRAM Program** | ✅ **每次成功** |

**结论**：

- **板上没有外部 SPI Flash**（两种模式都找不到）——
  > 注：早期文档里"这是外部 SPI Flash"的推断是**错的**，已在
  > `4k/fs/README.md` 开头加了「实测更正」。
- 片内 Flash 能擦能写，但校验失败；断电重上电后 `User Code = 0x00000000`，
  证实**没写进去**
- **每次 Flash 操作失败后，器件会锁在 POR 状态**，之后连 `SRAM Program`
  都报 `POR Down!`，**必须物理断电才能恢复**

**还没试的**：

1. **Gowin IDE 的 Programmer 图形界面** —— 命令行和 GUI 可能是不同流程
   （用之前记得先退出所有占用 USB 的程序）
2. 只有**断电后第一次** Flash 操作能进去。可以试：断电 → **直接**做
   `embFlash`（先不要烧 SRAM）
3. 换一块板子验证是不是硬件问题

**当前可用做法**：只烧 SRAM。板子能用，**但掉电后要重烧**（约 2.4 秒）。

### 8.3 🟡 串口通信未验证成功

**现象**：板载 USB 桥的串口通道（`/dev/cu.usbserial-11200` / `-11201`）
**读不到任何数据** —— 监听 4 秒（心跳每秒一行，本该收到 3~4 行），一行都没有。

**推测**：**引脚 44/46 可能并没有连到板载桥**。

**下一步**：用**外接 USB-TTL 模块**接 `TXD→46`、`RXD→44`、`GND→GND`，
一定能通。用户手上那几个 `/dev/cu.usbserial-*` 设备里应该就有可用的模块。

**注意**：`programmer_cli --scan` 能认出器件，说明 **JTAG 链路是好的**，
只是 UART 那一路的问题。

## 9. 踩过的坑（避免重复）

### 9.1 ⭐ 跨 always 块锁存晚一拍 —— **最惨的一次**

**现象**：4 个滑块不管拖哪个，效果都一样；而且滑块有一段完全没反应。

**根因**：接收组帧和数字锁存跨了两个 always 块。组帧块收到第 4 位时做移位，
锁存发生在**下一拍** —— 那时 `d1/d2/d3` 已经被移位覆盖了：

```verilog
// 组帧块
d0 <= d1; d1 <= d2; d2 <= d3; d3 <= rx_data;   // ← d1/d2/d3 被覆盖
fire <= 1'b1;

// 另一个块，下一拍
if (fire) begin
    cid <= d1;    // ← 读到的是"第 2 位"，不是舵机号！
```

**结果：舵机号变成了角度值的百位数字**：

| 滑块位置 | 发出的值 | 被当成舵机号 | 现象 |
|---|---|---|---|
| 0-49 度 | 000-098 | 0（非法）| **整段无反应** |
| 50-99 度 | 100-198 | 1 | 舵机 1 |
| 100-149 度 | 200-298 | 2 | 舵机 2 |
| 150-180 度 | 300-360 | 3 | 舵机 3 |

**修法**：锁存和移位放进**同一个 always 块**，用移位**前**的旧值锁存。

**为什么之前的验证没抓到（这条比 bug 本身更值得记）**：
我写的 Python 验证模型把 RTL 的**两个 always 块合并成了一步**，
正好绕过了这个 bug。**模型和 RTL 结构不一致时，模型通过 ≠ RTL 正确。**
后来改成**严格逐周期**建模（第 4 位后**再多跑一拍**让下一级看到 valid）
才复现出来。

**教训**：
1. 跨 always 块的"前一拍数据"不能想当然
2. **验证模型必须和 RTL 的 always 块划分对应**，不能只对应算法意图
3. 组合逻辑 bug 靠"读代码"和"综合通过"都发现不了

---

### 9.2 4 路完全相同的通道被综合器合并

4 个 `servo_pwm` 参数完全一样 → 综合器判定冗余 → **只留一路**，
4 个输出脚全被同一个信号驱动。

**修法**：加 `SERVO_PHASE_STEP = 22`，让 4 路的初始相位不同。

**教训**：多路相同实例要么加相位差，要么在综合脚本里设 `-no_prune`。

### 9.3 其它坑

| 坑 | 说明 |
|---|---|
| **`rPLL` 不存在** | GW1NSR-4C 的 PLL 原语是 **`PLLVR`**（多一个 `VREN` 输入）。用 `rPLL` 报 `EX0312` |
| **引脚 47/48** | 是 MSPI 专用脚，当普通 IO 报 `PR2017`；加 `-use_mspi_as_gpio 1` 能用，但**会失去 Flash 启动能力** |
| **隐式 1.8V** | 不写 `IO_TYPE` 会按 Bank 默认电压处理。**所有 IO 都显式写 `LVCMOS33`** |
| **引脚 10 = MODE1** | 当普通 IO 必须在 P&R 加 `set_option -use_mode_as_gpio 1` |
| **`.fs` 是只读的** | 权限 555，`cp` 会把权限带过去导致下次编译 `Permission denied`。脚本里先 `rm -f` 再 `cp` + `chmod 644` |
| **`gw_sh` 语法** | 器件要用 `set_device -name X Y`，**不是位置参数** |
| **macOS 跑 Gowin** | 要设 `DYLD_LIBRARY_PATH` 和 `DYLD_FRAMEWORK_PATH` 指向 `$IDE/lib` |
| **`set -e` + 管道** | `grep` 找不到时返回 1，会把整个脚本干掉。管道末尾要加 `\|\| true` |
| **Gowin IDE 占 USB** | 不退出 IDE 就烧录 → `Cable open failed` |
| **`servo_pwm` 复位值** | `pulse_r` 复位成 500µs（0°），但**两个时钟内就被 90° 覆盖**，输出从第一个脉冲起就是 1500µs。不是 bug |

## 10. 移植到 138K 时怎么做

**源码零改动**，只改两处：

1. `top.v` 里 `localparam CLK_FREQ = 27_000_000` → `50_000_000`
2. 约束文件：时钟引脚和舵机引脚换成 BX72 的

**已经验证过可行**（见 §7），Fmax 157 MHz。

### 移植时必须遵守的约定

- **`CLK_FREQ` 必须由每个例化处显式传递，绝不能用默认值** ——
  否则换时钟频率时静态检查抓不到
- **可移植模块里不能出现任何器件原语**（PLL、BRAM 等）
- 文件可以**逐字复制**（`uart_tx.v` 在两个工程里 SHA1 完全相同）

### 138K 工程已有的经验（`fpga_project/MOTOR_DRIVER.md`）

> 用**运行时除法器**导致 Fmax 从 87.586 MHz 掉到 29.275 MHz。
> 改成 3 级流水线（把除法换成定点乘法）后恢复。
> **这个工程里 `servo_pwm.v` 已经用了 3 级流水线，不要再退回除法。**
